# 回放时间轴交互补充设计

> 本文是 `2026-09-14-range-export-design.md` 的交互补充，并覆盖其中关于“现有单点点击/拖动 seek 行为继续保留”的笼统描述。时间轴应明确区分播放头拖动、背景平移与导出范围选择。

## 目标

在不重写 `PlaybackTimelineV3.vue` 的前提下，解决当前回放时间轴只能单击定位、播放头存在感弱、无法直观看到当前播放点的问题，并为时间范围导出提供一致的时间轴交互基础。

## 普通回放模式

普通模式保留单击定位，同时把当前播放位置升级为可见、可抓取的播放头。

### 播放头

- 当前播放点始终显示一条高对比竖线。
- 播放头顶部显示 `HH:mm:ss` 时间气泡。
- 增加明确的圆点/手柄命中区，命中区应大于视觉圆点，避免 1px 竖线难以抓取。
- 播放器播放时，播放头持续跟随 `activeWallSeconds` 更新。
- 播放头只表达当前播放位置，不因页面进入或 deep-link 自动启动播放。

### 拖动播放头

- `pointerdown` 命中播放头手柄后进入 `playhead-drag` 状态，并阻止背景平移逻辑。
- 拖动过程中实时更新视觉播放头和时间气泡。
- 为避免高频 seek 导致视频解码/网络请求抖动，拖动过程的实际 seek 采用轻量节流；`pointerup` 时提交最终 seek。
- 如果拖到无录像区，播放头允许停在该墙钟时间，时间轴明确显示“无录像”；不自动吸附到最近切片，避免用户误解真实时间位置。
- 在无录像位置释放后，播放器保持当前媒体状态，不自动启动其他录像；用户再次定位到有效录像时才执行正常 seek。

### 单击定位

- 单击有效录像区域仍直接 seek，兼容现有习惯。
- 单击无录像区域只移动墙钟播放头并显示“无录像”，不自动寻找最近录像。
- 单击与拖动通过移动阈值区分，避免 `pointerup` 后重复触发 click seek。

### Hover 时间预览

- 鼠标位于主时间轴时显示一条低强调预览线和 `HH:mm:ss` 浮层。
- Hover 只预览时间，不改变播放位置、不触发 seek、不改变媒体状态。
- 鼠标离开后预览线消失。
- 在触摸设备上不依赖 hover；触摸继续使用点击/拖动。

## 时间窗口平移与缩放

保留现有缩放和平移能力，但事件语义明确化：

```text
拖播放头手柄       -> 调整播放时间
拖主时间轴背景     -> 平移当前时间窗口（仅 6h / 1h / 15m）
滚轮               -> 以指针位置为锚点缩放
单击               -> 定位播放点
```

- 24h 视图不做背景平移，沿用现有行为。
- 播放头拖动优先级高于背景平移。
- Hover 预览没有 pointer capture，不影响拖动。

## 导出范围模式

点击“导出片段”后，时间轴进入独立 `range-select` 模式。

- 出现开始、结束两个范围手柄。
- 两个手柄分别显示真实墙钟时间。
- 选中区域使用半透明高亮。
- 支持拖动开始手柄、结束手柄以及整体移动选区。
- 当前播放头仍显示，但视觉层级降低，避免与范围边界混淆。
- 导出范围选择不触发播放器自动播放。
- 退出/取消导出后恢复普通播放头交互。

范围选择模式下，主时间轴背景拖动和平移仍可保留，但手柄/选区拖动拥有更高事件优先级。

## 组件状态建议

`PlaybackTimelineV3.vue` 内部将 pointer interaction 明确为互斥状态，而不是多个布尔值互相竞争：

```text
idle
pan
playhead-drag
range-start-drag
range-end-drag
range-move
```

这能避免播放头拖动、时间轴平移和范围选择同时响应同一个 pointer 序列。

组件新增/调整事件建议：

```text
seek-preview(seconds)      // 可选，节流后的拖动预览
seek-commit(seconds)       // 单击或拖动结束后的最终 seek
range-change({start,end})  // 选区拖动中的视觉更新
range-commit({start,end})  // 选区拖动结束
```

`PlaybackWorkspace.vue` 继续负责真正的播放器 seek、导出范围状态和导出业务，不把 FFmpeg/API 逻辑放进时间轴组件。

## 视觉层级

普通模式：

```text
                    10:08:36
                       ▼
录像 █████████████████│██████████
移动        ██         │     ███
                       ●
```

导出模式：

```text
      10:03:20                 10:17:45
          ▼                        ▼
──────────●════════════════════════●──────────
                    │
                 当前播放头
```

要求：

- 播放头在深色/浅色主题都必须清晰。
- 时间气泡使用等宽数字视觉（tabular nums）。
- 命中区不应依赖 1px 线本身。
- 不能通过加大整条 overlay 的 cursor 来伪装可拖动；真正的播放头必须有独立 hit target。

## 测试

前端回归测试至少覆盖：

- 当前播放位置会渲染明显播放头与时间文本。
- 播放头拥有独立 pointer 命中区，而不是 `pointer-events:none`。
- 拖动播放头不会触发背景 pan。
- 背景拖动仍能平移 6h / 1h / 15m 视图。
- 单击仍能提交 seek。
- hover 预览不触发 seek。
- 无录像区定位不自动播放或吸附到其他录像。
- `activeWallSeconds` 更新会同步播放头。
- range-select 模式下双手柄优先于播放头和背景 pan。
- 退出 range-select 后恢复普通播放头行为。

## 与范围导出设计的关系

该交互优化与导出功能一起实施，但可以独立测试。实现顺序建议先完成普通播放头交互，再在同一时间轴状态机上增加 range-select，避免一次性叠加两套 pointer 行为后难以定位回归。
